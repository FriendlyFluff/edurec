# Автономный агрегатор с семантической дедупликацией (Autonomous Harvester)

Мы переходим от прямого веб-поиска мероприятий (через поисковые API вроде DuckDuckGo) к двухконтурной системе агрегации (Разведчик + Сборщик). Причина: публичный поиск возвращает много "мусорных" данных (коммерческие курсы, нерелевантные статьи) и часто блокируется анти-бот системами при работе из облака. Мы также вводим композитный ключ дедупликации (Название + Дата + Целевая аудитория) для предотвращения склейки мероприятий для разных классов.

## Considered Options

- **Прямой поиск через DuckDuckGo / Tavily API**: Отклонено, так как результаты содержат много нерелевантных страниц, и парсинг "на лету" хрупок.
- **Жестко захардкоженные источники (RSS)**: Отклонено, так как структура источников меняется, сайты могут закрыться, а ручная поддержка списка — это "костыль".
- **Двухконтурная система (Scout + Harvester) с Jina Reader**: Принято. Разведчик (Scout) использует поисковик для нахождения и верификации "надежных источников". Сборщик (Harvester) парсит только проверенные источники напрямую через Jina Reader, минуя капчи и сложный HTML.

## Consequences

- Нам потребуется создать новую таблицу `trusted_sources` в Supabase.
- Значительно снизится нагрузка на поисковые API, так как поиск используется только для обнаружения новых порталов (Scout), а не для ежедневного сбора мероприятий.
- Придется написать более сложные промпты для LLM, чтобы она умела фильтровать коммерцию и определять статус "смерти" сайта.
