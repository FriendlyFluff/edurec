# 1. Cloud Architecture & Data Persistence for EduRec

Date: 2026-10-08

## Status

Accepted

## Context

Проект EduRec изначально разрабатывался как локальный скрипт: сбор данных происходил через тяжелый браузер (Playwright), аналитика генерировалась локальной LLM (LM Studio), а данные хранились в локальном файле `edu_events.db` (SQLite). 

Для защиты проекта перед университетской комиссией потребовалось обеспечить публичный доступ (через QR-код), мгновенное время отклика и 100% бесплатность 24/7. 

Развертывание на бесплатном хостинге Streamlit Community Cloud выявило следующие архитектурные проблемы:
1. Streamlit Cloud обладает жестким лимитом RAM (1 ГБ). Запуск headless-браузера Playwright вызывает ошибки Out Of Memory.
2. Streamlit Cloud является эфемерной средой: локальный файл SQLite будет сбрасываться до состояния репозитория при каждом засыпании/перезапуске приложения, что приведет к потере новых собранных данных.
3. Отсутствие GPU в бесплатном облаке делает невозможным запуск локальных моделей.

## Decision

Мы приняли решение полностью перевести стек на бесплатные облачные SaaS-решения, обеспечивающие производительность уровня Production без финансовых затрат:

1. **Замена SQLite на Supabase (PostgreSQL):**
   Данные вынесены за пределы эфемерного контейнера. Supabase предоставляет надежную облачную СУБД с достаточным бесплатным тарифом (500 МБ). Файл `database.py` будет переписан под адаптер `psycopg2` / `supabase-py`.
2. **Замена Playwright на DuckDuckGo Search API:**
   Для предотвращения падений сервера из-за нехватки памяти (OOM), тяжелый парсер заменен на легковесный API-запрос к поисковику. Результаты (сниппеты) извлекаются за секунды и передаются в LLM.
3. **Замена LM Studio на Groq API:**
   Мы используем облачный API Groq, который предоставляет доступ к открытым моделям со сверхвысокой скоростью вывода.
   - Для сложных рекомендаций RAG используется **LLaMA-3-70B**.
   - Для фонового извлечения метаданных парсером используется легковесная **LLaMA-3-8B** (во избежание превышения Rate Limits на бесплатном тарифе).

## Consequences

**Положительные:**
- Проект становится полностью автономным, доступным по ссылке 24/7.
- Мгновенная генерация ответов RAG для комиссии (эффект "Вау").
- Данные защищены от сброса при перезагрузке сервера.
- Запуск парсера в облаке происходит без падений и блокировок интерфейса.

**Отрицательные:**
- Требуется рефакторинг `database.py` под PostgreSQL (вместо SQL-запросов SQLite).
- Незначительное снижение глубины поиска по региональным сайтам РФ из-за перехода с Yandex на DuckDuckGo (не критично для целей демонстрации комиссии).
- Зависимость от ключей API (Groq, Supabase), которые необходимо хранить в Секретах (Streamlit Secrets).
